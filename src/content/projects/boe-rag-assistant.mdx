## The Problem

Most RAG demos are English-only toys with no measurement story. This one targets a real, daily-updated Spanish legal corpus — the **BOE** (Boletín Oficial del Estado) — and treats retrieval quality as an engineering problem rather than a vibe check. Every answer cites the exact article of the law it comes from, with links back to boe.es.

The guiding principle is **eval-first**: a golden QA dataset and retrieval metrics (recall@k, MRR, nDCG) exist *before* any optimization, and CI blocks merges that regress them. No retrieval or generation change ships without a before/after benchmark.

### Structure-aware ingestion

The ingestion layer turns the BOE Open Data API into a clean, retrieval-ready corpus. A resilient HTTP client (timeouts, polite rate limiting, retry-with-backoff) feeds a parser that flattens the daily *sumario* JSON and parses each document's XML into typed metadata and ordered body blocks. The **chunker walks the legal hierarchy** (título → capítulo → sección → artículo) and emits one chunk per article with its full context — so every passage can cite the exact article it came from. Chunks serialize to Parquet for the Hugging Face Hub.

## Evaluation

The harness scores the retriever against a hand-curated golden set of real Spanish legal questions, each mapped to the chunk that answers it. Metrics are pure-Python and run in CI. Two tiers keep measurement honest: 20 hand-curated *gold* questions are the source of truth, and a larger LLM-generated *silver* set (faithfulness-filtered by an LLM judge) scales coverage — reported separately, since synthetic questions can flatter the system that generated them.

**Baseline** — `intfloat/multilingual-e5-small`, dense-only retrieval, 2024 corpus (2,225 chunks, 20 questions):

| Recall@10 | Hit rate@10 | MRR | nDCG@10 |
|---|---|---|---|
| 0.900 | 0.900 | 0.749 | 0.783 |

## Retrieval Engineering

Sparse and dense retrieval fail differently: BM25 nails exact legal references (`artículo 14`, `Ley 39/2015`) but misses paraphrases; the embedding model matches meaning but misses rare terms. A pure-Python BM25 index is fused with the dense retriever by **Reciprocal Rank Fusion**, then a **cross-encoder** reranks a 30-candidate pool as a sharp second stage.

| Retriever | Recall@10 | Hit rate@10 | MRR | nDCG@10 |
|---|---|---|---|---|
| dense (baseline) | 0.900 | 0.900 | 0.749 | 0.783 |
| BM25 | 0.900 | 0.900 | 0.732 | 0.773 |
| hybrid (RRF) | 0.900 | 0.900 | 0.763 | 0.793 |
| **hybrid + cross-encoder** | **1.000** | **1.000** | **0.888** | **0.913** |

Reranking breaks the recall ceiling — **0.900 → 1.000** — by promoting two hard questions that were in the candidate pool but ranked too low, with **MRR +0.125 and nDCG +0.120** over hybrid. A separate chunking ablation validates the production choice: article-level chunks match whole-document ranking quality *and* uniquely support exact article citations, while fixed-size windows rank the right document lower (MRR −0.063) because they fragment articles.

## Grounded Generation

A provider-agnostic LLM layer (Gemini + Groq, with a fallback chain that trips a circuit breaker on a rate-limited provider) powers a cite-or-refuse answerer and an **LLM-as-judge** that scores each answer for faithfulness (grounded in the retrieved passages?) and correctness (matches the reference?).

| Mean faithfulness | Mean correctness | Refusal rate |
|---|---|---|
| 0.990 | 0.895 | 0.050 |

Near-perfect faithfulness confirms the cite-or-refuse prompt rarely hallucinates; correctness is the headroom that future retrieval and generation work will target.

## Serving

The measured pipeline — hybrid retrieval → cross-encoder rerank → grounded generation — is composed behind an `Engine` protocol and served by a **FastAPI** app (`/health`, `/search`, `/ask`, with response caching and per-client rate limiting to protect the free LLM tier). The HTTP layer is unit-tested with a fake engine, so CI needs no models or API keys. A **Gradio** chat UI is mounted on the same app and shares one engine, so the demo and the JSON API can never drift; it links each source back to boe.es and degrades gracefully to showing retrieved passages when the LLM tier is rate-limited.
