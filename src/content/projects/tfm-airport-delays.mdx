## The Problem

Airline delays cascade across the US air network. Predicting which airports will be affected, and when, is a graph problem with both spatial (route topology) and temporal (time-of-day, weather) structure. A delay at a single hub on a Monday morning can ripple through dozens of downstream airports over the following hours — and traditional time-series models miss the topology that drives the propagation.

## The Approach

Modeled the US airport network as a directed graph over the 70 busiest airports (nodes = airports, edges = flight routes). Progressively built models from dense networks and LSTMs, through Graph Convolutional Networks (GCN) and Graph Attention Networks (GAT), to the final architecture: a spatio-temporal Transformer.

- **Spatial encoder** — three stacked GATv2 layers with pre-norm residual connections, consuming 5-channel edge features (scheduled traffic, recent route delay).
- **Temporal encoder** — a 2-layer Transformer with sinusoidal positional encoding over a 6-hour window of graph snapshots.
- **Horizon-query decoder** — learnable query embeddings cross-attend to each airport's temporal sequence, one query per forecast horizon. No autoregression, so an early miss can't cascade into the longer horizons.

The GATv2 layer computes the attention coefficient between airport $i$ and neighbor $j$ as:

$$\alpha_{ij} = \frac{\exp(\vec{a}^T \text{LeakyReLU}(\mathbf{W} [\vec{h}_i \,\|\, \vec{h}_j]))}{\sum_{k \in \mathcal{N}_i} \exp(\vec{a}^T \text{LeakyReLU}(\mathbf{W} [\vec{h}_i \,\|\, \vec{h}_k]))}$$

Unlike the original GAT, applying the attention vector *after* the non-linearity makes the attention dynamic — the ranking of neighbors can change per query node. That matters when a single hub disproportionately drives delay propagation.

## The Pipeline

Processed Kaggle's 2018–2022 US flight delay dataset (~7M flights/year, ~35M total) through a modular pipeline, training on 2018–2019 with strict temporal train/val/test splits. Reproducible setup with YAML hyperparameter management, snapshot caching, and unit tests.

- **Preprocessing**: temporal alignment, missing-value imputation, feature scaling, splits by date.
- **Graph construction**: hourly snapshots of the 70-airport network — directed route edges with traffic/delay features, node features combining rolling delay statistics with live weather (wind, precipitation, cloud cover) from Open-Meteo.
- **Training**: multi-horizon (1h, 2h, 4h, 6h, 8h) regression on per-airport mean arrival delay, with a multi-task loss: weighted Huber that up-weights delayed samples, an auxiliary departure-delay head, and a BCE head classifying ≥15-minute delays.
- **Evaluation**: MAE/RMSE/R² per horizon, plus precision/recall/F1 at the 15-minute operational threshold, with decision-threshold sweeps to trade precision for recall.

On the held-out test period the model reaches **MAE ≈ 10 min, RMSE ≈ 18 min, R² 0.25** averaged across horizons.

## Deployment

The trained model runs as a demo production system on Azure + Microsoft Fabric:

- An **Azure Function** replays the 2022 season as a live ingestion API, writing hourly partitions (actuals, schedule, and a 168-hour rolling feature buffer) to OneLake.
- A **Fabric Data Factory pipeline** triggers an inference notebook every hour, loading the champion checkpoint and writing 350 predictions (70 airports × 5 horizons) to Delta tables.
- A dashboard and a predictions REST API consume those tables; a monthly champion/challenger retraining pipeline on Azure ML is scaffolded as the production-extension path.

## Code

The spatial encoder stacks GATv2 layers with pre-norm residuals — the residual stream keeps gradients healthy and counteracts the over-smoothing of deep GNN stacks:

```python
# Pre-norm residual stack.
for conv, norm in zip(self.layers, self.norms):
    h = norm(x)
    h = conv(h, edge_index, edge_attr=edge_attr)
    h = F.gelu(h)
    h = F.dropout(h, p=self.dropout, training=self.training)
    x = x + h
```
